      27-November-2026 - 7.30.0-SNAPSHOT

      The PMD team is pleased to announce PMD 7.30.0-SNAPSHOT.

      This is a minor release.

      🚀️ New and noteworthy

      🌟️ New and Changed Rules

      New Rules

      • The new Java rule ControlFlowInTest reports control flow in test methods that can obscure which assertions are executed. It checks conditionals, switch statements and expressions, explicit throw statements, try statements with catch clauses, and plain try-finally statements. Loops are allowed by default and can be reported by setting allowLoops to false.

      Deprecated Rules

      • The Java rule AddEmptyString is deprecated without replacement and will be removed with PMD 8.0.0. Its performance claim is not valid on modern JDKs: constant string concatenations are evaluated at compile time, and replacing concatenation with toString() or String.valueOf() does not generally improve performance. The rule is excluded when referencing the whole Performance category, but explicit rule references continue to work during the deprecation period.

      🚨️ API Changes and Deprecations

      Experimental API

      • kotlin
        • KtVariableDeclarationAttributes now implements HasTypeName, so VariableDeclaration nodes have a @TypeName attribute. This covers property and for-loop variables, lambda parameters, and each component of a destructuring declaration (val (a, b) = ..., for ((a, b) in ...), { (a, b) -> ... }). The XPath functions pmd-kotlin:typeIs, pmd-kotlin:typeIsExactly and pmd-kotlin:isNullable support VariableDeclaration nodes as well.
        • A destructuring PropertyDeclaration (e.g. val (a, b) = Pair(1, "x")) no longer has a @TypeName. Before, it wrongly got the type of the first component. To find destructured variables by type, query the component nodes instead: //VariableDeclaration[pmd-kotlin:typeIs('kotlin.Int')].
